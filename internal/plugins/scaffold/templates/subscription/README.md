# __PLUGIN_ID__

A Quivr alert-rule plugin generated by `quivr plugin init --kind subscription`.
It implements the `subscription` Contribution (Plugin API 0.2): Quivr sends
one new or corrected article (a Record Version's text Parts and its metadata:
source, acceptance time, provenance and extensions) together with a batch of
saved searches to check, and the rule answers `match`, `no_match` or
`not_ready` for each one. The template's rule is deliberately simple. An
article matches:

- `{"kind": "substring", "text": "..."}`: when a phrase appears in one of its
  text Parts, ignoring case unless the Subscription asks for `case_sensitive`;
- `{"kind": "metadata", "pointer": "/provenance/producer", "equals": "..."}`:
  when a metadata field, named by a JSON Pointer into the article's
  `source`, `provenance`, `extensions` or `accepted_at`, has that value.

The expression's JSON Schema is `expression_schema` in `quivr-plugin.yaml`;
Quivr validates saved searches against it when a Subscription pins them and
refuses an invalid one (422 `invalid_expression`). To offer another kind of
alert, add a `oneOf` branch with its own `kind` and handle it in `rule.py`.

Quivr asks the rule when an article becomes searchable, and asks again once
its embeddings are attached if the rule answered `not_ready`. A rule that
needs enrichment answers `not_ready` while `invocation.enriched` is false.

## Set up

Python 3.12 or later. Install the Quivr Plugin SDK from the Quivr repository:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e <path to a quivr-v2 checkout>/sdks/python
# or: pip install "quivr-plugin-sdk @ git+https://github.com/The-Vibe-Company/quivr-v2#subdirectory=sdks/python"
```

## Develop

```bash
quivr plugin inspect .                              # validate quivr-plugin.yaml
python3 -m unittest discover -s tests               # unit tests
quivr plugin dev --fixture fixtures/sample.json     # run the plugin and replay the fixture once
quivr plugin test --report contract-report.json     # certify the plugin with the Contract Runner
```

A subscription fixture holds an article's Parts and the evaluations to
decide, each with an optional `expect`ed decision. `quivr plugin test` sends
every fixture in `fixtures/` in batches of at most `max_batch_size`, checks
one decision per evaluation with evidence Quivr can store (an explanation of
at most 4096 characters, at most 100 Part keys that exist, details of at most
16 KiB), compares the expected decisions, replays each batch, sends it again
in reverse order (a decision must not depend on its position), sends invalid
requests, and exits `0` only when Quivr can safely call the rule.

## Layout

| Path | Purpose |
| --- | --- |
| `quivr-plugin.yaml` | Identity, compatibility, expression and configuration schemas, batch size, run command |
| `__PLUGIN_MODULE__/rule.py` | The alert rule |
| `__PLUGIN_MODULE__/__main__.py` | Serves the plugin over HTTP |
| `fixtures/` | Subscription fixtures |
| `tests/` | Unit tests using `quivr_plugin.testing` |

Raise `quivr_plugin.RetryableError` for transient failures, such as a remote
classifier that is unavailable: Quivr retries and never records a negative
decision. Raise `quivr_plugin.TerminalError` for an evaluation the rule can
never decide. Every change to `quivr-plugin.yaml` changes its digest; restart
the plugin so discovery serves the new one.
