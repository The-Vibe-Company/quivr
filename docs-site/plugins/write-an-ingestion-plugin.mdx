An ingestion plugin decides how each Version's text is cut into passages (segments) and turned into vectors, and encodes search queries with the same model. Quivr keeps the index, the registry of vector spaces, rebuilds, access control and withdrawals. This page starts from the SDK's sample, which embeds by hashing words, so you can replace its model with yours.

## Prerequisites

- Go 1.24 or later, a `quivr-v2` checkout in `$QUIVR_REPO`, and the `quivr` command on your `PATH` ([Build your first plugin](/plugins/first-plugin) shows how).
- To move existing Corpora onto the plugin, an API key with the `projections:rebuild` and `operations:read` actions.

## Steps

<Steps>
<Step title="Start from the sample">

```bash
cp -r "$QUIVR_REPO/sdks/go/examples/hash-embedder" my-embedder && cd my-embedder
go mod init example.com/my-embedder
go mod edit -replace github.com/The-Vibe-Company/quivr-v2/sdks/go="$QUIVR_REPO/sdks/go"
go mod tidy
```

</Step>
<Step title="Declare your vector spaces">

A vector space is one model with its dimensions and distance. Your plugin owns every space it declares, so each space id is the plugin id or starts with it. Edit `quivr-plugin.yaml`:

```yaml quivr-plugin.yaml
id: acme.embedder
version: 0.1.0
compatibility:
  engine: ">=0.1.0 <0.2.0"
  plugin_api: ">=0.8.0 <0.9.0"
contributions:
  ingestion:
    spaces:
      acme.embedder.base:
        version: "1"
        model: acme/text-embed-base
        dimensions: 768
        metric: cosine
        indexes: [text]
        query_modalities: [text]
    timeout_ms: 10000
    query_timeout_ms: 1000
run:
  command: [go, run, .]
```

Bump a space's `version` whenever its vectors change: a new model, new weights, a new input template. Quivr treats `acme.embedder.base@2` as a new space and never mixes its vectors with those of version 1. Declare several spaces to compare models: a deployment serves search from one and indexes the others for evaluation.

</Step>
<Step title="Implement the two operations">

`main.go` registers one type with two methods:

- `SegmentAndEmbed` receives the Version's text Parts and the spaces to fill. It returns segments in reading order, each with the Part key, `start` and `end` offsets in Unicode code points, and one vector per requested space. It may add a `LexicalText`, indexed for keyword search while excerpts keep the source text, and a `Provenance` map.
- `EmbedQuery` returns the vector of one search query in one space. A search waits for it, within `query_timeout_ms`.

Replace `hashWords` with a call to your model. Both methods must be deterministic: rebuilds reuse stored segments and vectors, and Quivr refuses a different answer for the same Version. When a Version arrives, Quivr first asks for the segments alone, with no spaces, so the article is searchable by keyword even while your model is down; it asks for the vectors afterwards. Return the same segments both times.

Return `quivrplugin.RetryableIngestError` when your model is unavailable: the Version waits and is retried. Return `TerminalIngestError` for content you can never handle: the Version is blocked with `ingestion_refused`, and its diagnostic shows your error's code and message, so say in plain words why, such as `no_indexable_text`.

A call that runs past `timeout_ms` (at most 5 minutes) is cancelled and retried, and after three such calls the Version's enrichment stops. If your model is slow on long Versions, keep the vectors you already computed and return a retryable error before the deadline: the next call resumes instead of starting over.

</Step>
<Step title="Certify it">

```bash
quivr plugin test --startup-timeout 120s .
```

The Contract Runner sends the normative article and your fixtures in `fixtures/`, checks every segment and vector as the engine will, replays each fixture, compares the segments-only answer with the full one, and encodes the fixture queries in every space. Set a fixture's `expect.segments` to pin your segmentation.

</Step>
<Step title="Pin it">

Several ingestion plugins can run beside `core.ingest`; [source media routing](/reference/configuration#ingestion-routing) chooses one per Version. To use yours alone, pin it in the configuration of every `api`, `worker` and `migrate` process, and say which space serves search:

```json QUIVR_CONFIG
{"plugins": [
  {"manifest": "/etc/quivr/plugins/acme-embedder/quivr-plugin.yaml",
   "endpoint": "http://127.0.0.1:9950",
   "spaces": {"acme.embedder.base": "served"}}
]}
```

At startup Quivr registers each space with its owner. It refuses a space another plugin already registered (`space_owner_conflict`), and a registered space whose model, dimensions or metric changed without a new version (`space_changed`).

</Step>
<Step title="Move a Corpus onto it">

New Corpora use the plugin at once. An existing Corpus keeps the spaces it was built with, and stays searchable, until you rebuild it:

```bash
curl -s -X POST "$QUIVR_API_URL/v0/corpora/$CORPUS_ID/rebuilds" -H "Authorization: Bearer $QUIVR_API_KEY" \
  -H "Content-Type: application/json" -d '{"idempotency_key": "move-to-acme-embedder"}' | jq '{operation_id, state}'
```

The rebuild asks each Version's routed plugin for every Version without vectors in the new spaces, then switches search over at once. Follow it with `GET /v0/operations/{operation_id}`.

</Step>
</Steps>

## Check it worked

```bash
curl -s "$QUIVR_API_URL/v0/corpora/$CORPUS_ID/vector-spaces" -H "Authorization: Bearer $QUIVR_API_KEY"
```

The response lists the Corpus's spaces with their owner, their role (`served` or `evaluation`) and how many segments hold a vector in each. Search hits name the space that answered in `vector_space_id`.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| New Versions wait, semantic search answers 503 | The plugin is down or returns a retryable error. Keyword search keeps working. |
| A Version is blocked with `ingestion_refused` | The plugin returned a terminal error, or segments and vectors the checks refuse (offsets out of range, wrong dimensions, too many segments). The Version's diagnostic names which. |
| Enrichment is blocked with `derivation_conflict` | The segments returned with vectors differ from those first returned alone, or the plugin answered the request for vectors with a terminal error. |
| Enrichment is blocked with `enrichment_timeout` | Three calls for the Version ran past `timeout_ms`. The Version stays searchable by keyword. |
| Searches fail with `422 query_too_long` | `embed_query` refused the query with the code `query_too_long`; its message, such as `query exceeds 256 tokens`, is returned to the client. |
