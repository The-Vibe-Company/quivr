`quivr api`, `quivr worker` and `quivr migrate` read one JSON file, whose path is in the `QUIVR_CONFIG` environment variable. Give every process the same file, except for addresses such as `probe_listen`. `make dev` writes one for the local stack; this page lists every field. `make docs` fails when a field of the engine's configuration is missing here.

## Top-level fields

| Field | Required | Meaning |
| --- | --- | --- |
| `database_url` | yes | PostgreSQL connection URL, such as `postgres://quivr:…@db:5432/quivr?sslmode=verify-full` |
| `cursor_key` | yes | A secret of at least 32 bytes that signs change-feed cursors. Keep it stable. |
| `keys` | yes | The API keys, by bearer token. See [API keys](#api-keys). |
| `temporal_address` | yes | Temporal's frontend address, such as `temporal:7233` |
| `telemetry` | no | Opt-in OTLP traces and metrics export. See [OpenTelemetry](#opentelemetry). |
| `tls` | no | Outgoing connection encryption and trust. See [Outbound TLS](#outbound-tls). |
| `weaviate_url` | yes | The Weaviate search index, such as `http://weaviate:8080` |
| `s3` | yes | Object storage for original bytes and derived artifacts. See [Object storage](#object-storage). |
| `listen` | no | Address of the public HTTP API. Default `127.0.0.1:8080`. |
| `probe_listen` | no | Private address of `/healthz`, `/readyz` and `/metrics`. Default `127.0.0.1:8081`; give each process its own. |
| `log_level` | no | Minimum log level: `debug`, `info` (default), `warn` or `error`. `QUIVR_LOG_LEVEL` overrides the file. |
| `instance` | no | Process identity in each log event. Default hostname and PID; `QUIVR_INSTANCE` overrides the file. |
| `environment` | no | Deployment environment label in each log event. Default `unspecified`; `QUIVR_ENVIRONMENT` overrides the file. |
| `shutdown_grace` | no | Shared grace period for draining HTTP requests and background work after SIGTERM or SIGINT. Positive Go duration, default `60s`; `QUIVR_SHUTDOWN_GRACE` overrides the file. |
| `log_directory` | no | Also write JSON logs to rotating files in this folder; stdout remains enabled. Four files per process, up to 1 MiB each. |
| `retrieval` | no | Search profile aliases. See [Search profiles](#search-profiles). |
| `plugins` | no | The plugins this deployment calls. See [Plugin pins](#plugin-pins). |
| `ingestion_evaluation_concurrency` | no | Evaluation activities in flight per worker. Default `4`, range `1`–`32`; `0` selects the default. Served ingestion has separate capacity. |
| `ingestion` | no | Source media routing and the default ingestion plugin. See [Ingestion routing](#ingestion-routing). |
| `plugin` | no | One pin, shorthand for a one-item `plugins` list; both may be combined |
| `destinations` | no | Webhook destinations for alerts. See [Webhook destinations](#webhook-destinations). |
| `delivery` | no | Webhook retry policy, worker only. See [Delivery](#delivery). |
| `credential_key` | no | A secret of at least 32 bytes that encrypts connector credentials at rest. Without it, credentials are refused with `503 credentials_unavailable`. Keep it identical on api and worker, and stable. |
| `public_url` | no | The address where sources reach this API, such as `https://quivr.example.com`. Connector kinds that receive webhooks need it. |
| `connector_min_interval` | no | Shortest polling interval an instance may ask for, a Go duration. Default `30s`. |
| `connector_push` | no | Declared source API protection: `rate_per_second` (default `10`, range `0.001`–`100000`), `burst` (default `100`, maximum `100000`), `idempotency_ttl` (Go duration, default `24h`, range `1ms`–`168h`) and `trusted_proxy_cidrs` (default empty). Instance `push_policy` can override rate/burst and set `allowed_cidrs`. |
| `change_retention` | no | How long the change feed keeps events and a cursor stays valid. Default `168h` (7 days). |
| `change_stream_poll` | no | How often an open change stream (`/v0/changes/stream`) checks for new events. Shorter delivers sooner and reads the database more often. Api only. Default `250ms`. |
| `change_prune` | no | When the worker prunes the change feed. See [Change feed pruning](#change-feed-pruning). |
| `pinned_plugin_attempts` | no | How many attempts work pinned to an earlier Pipeline Plan gets when one of that plan's plugins, no longer in the active plan, cannot be reached, before it stops with `pinned_plugin_unavailable`. Worker only. Default `10`. |
| `plugin_plan_poll` | no | How often api and worker check whether the active Pipeline Plan changed, to follow it without restarting. Default `2s`. |
| `observability` | no | Counters of plugin calls, searches, document steps, documents received and Matches, read with an `observability:read` key. See [Observability](#observability). |
| `backfill` | no | How backfills run and when their cost needs a confirmation. See [Backfill](#backfill). |
| `migration_wait` | no | How long a worker that starts before the api has applied its migrations waits for them, unready, before it exits. `0s` exits at once. Worker only. Default `5m`. |
| `projection_purge_grace` | no | How long search objects of superseded Versions are kept before they are deleted, worker only. Default `1h`. |
| `tei_url` | no | A Text Embeddings Inference server that encodes queries for Corpora built before the `core-ingest` plugin; not needed on a new deployment |
| `m365` | no | Refused. The Microsoft 365 settings moved to the `m365-mail` plugin's pin configuration. |

Durations are Go durations: `30s`, `10m`, `168h`. Unknown fields refuse startup. Remove the former `connector_fixtures` and `monitoring_fixture_evaluator` settings; the acceptance harness now pins its fixture plugin through `plugins`.

## Logs and shutdown

Engine processes write one JSON event per line to stdout. Every event includes `ts`, `level`, `msg`, `service`, `version`, `instance`, `environment`, `trace_id` and `span_id` (empty outside a trace); events within an HTTP request also include `request_id`. `service` distinguishes `quivr.api`, `quivr.worker` and `quivr.migrate`. `version` reports the engine build version. Debug events are hidden at the default `info` level. Nonempty environment overrides take precedence over the JSON file; unknown levels and nonpositive grace periods refuse startup.

Each completed public or probe HTTP request writes an access event with `route`, `method`, `status`, `duration_ms`, `response_size` (bytes written), `client_ip`, `api_key_id`, `error_code` and `request_id`. Routes are registered templates, with `unmatched` for unknown paths. For public requests, client IP follows the trusted proxy policy in `connector_push.trusted_proxy_cidrs`; otherwise it is the socket peer. Probe requests use the socket peer. The key ID is a 128-bit SHA-256 fingerprint of a bearer token present in the configured `keys`; it is empty for instance tokens and requests without a configured API key. No bearer token, request body, query string or arbitrary request path is logged.

Lifecycle events use `event`: `quivr.start`, `quivr.ready`, `quivr.draining` and `quivr.stop`. Startup includes an allowlisted summary of effective process settings, with counts and enabled flags for sensitive configuration. Credentials, plugin settings and connection URLs are excluded. Raw error details are redacted at the logging boundary; use stable event and error codes for routing.

On SIGTERM or SIGINT, readiness becomes `503` before drain begins. New public requests are refused, public listeners close, and admitted work can finish within one `shutdown_grace` budget. Probes remain available during the drain. Work still running at the deadline is canceled, open HTTP connections are closed, and unfinished durable work can resume on another worker. Streaming connections count as in-flight requests and may use the whole grace period. The final counter flush shares this deadline.

## OpenTelemetry

Set `telemetry.endpoint` in every engine process to export traces and metrics to your collector. An omitted or empty endpoint disables export; tracing uses a no-op provider and installs no dependency tracing or exporter goroutines. `/metrics` remains available with the same Prometheus metric names, labels and buckets. SDK meters own aggregation; no collector is needed for scraping. The OTLP reader samples backlog gauges even when nobody scrapes `/metrics`.

| Field | Default | Meaning |
| --- | --- | --- |
| `endpoint` | Empty (export off) | Collector base URL, such as `https://collector.example.com:4318`. HTTP appends `/v1/traces` and `/v1/metrics`; gRPC permits no path. URLs with credentials, queries or fragments are refused. |
| `protocol` | `http/protobuf` | `http/protobuf` or `grpc`. Use an `https` endpoint for verified TLS, or `http` for plaintext to a trusted local collector. |
| `headers` | `{}` | Collector authentication headers, used for both signals. Values are excluded from logs. |
| `sampling_ratio` | `1` | Root trace sampling probability, from `0` to `1`. Children honor their parent's sampled flag, including incoming W3C context. |
| `resource_attributes` | Engine service and version | Deployment identity as string key/value pairs. `service.name` and `service.version` use process settings. Configured `instance` and `environment` also become resource attributes unless you override them. |

For example, not run:

```json
{"telemetry":{"endpoint":"https://collector.example.com:4318","protocol":"http/protobuf","sampling_ratio":0.1,"resource_attributes":{"deployment.environment.name":"staging"}}}
```

The API honors W3C `traceparent` and `tracestate`. Send `X-Request-ID` as 1–128 ASCII letters, digits, dots, underscores or hyphens; missing, duplicate or invalid IDs are replaced. Responses echo `X-Request-ID`; JSON errors include `request_id` and, when a valid trace context is present (including an incoming `traceparent` while export is disabled), `trace_id` and `span_id`. Logs carry the same trace fields. Request IDs are correlation values, so use opaque IDs rather than names or secrets.

One trace crosses durable ingestion and operation queues, Temporal workflows and activities, plugin calls, monitoring evaluation and webhook retries. Spans cover HTTP route templates, PostgreSQL, Weaviate and S3. They exclude SQL statements, query text, URLs, object keys, record identifiers, bodies and baggage. Resource attributes are operator-controlled: keep customer data out of them. `observability.record_query_text` only governs the stored search statistics below, not span attributes.

Export runs asynchronously. A collector outage does not stop requests; the SDK's bounded queue can drop telemetry. Look for `quivr.telemetry.export_failed`, with no collector credentials or raw error details. Shutdown flushes exporters within the shared grace deadline. Plugin SDKs continue W3C context automatically; configure an exporter separately in each plugin process to observe its internal spans. See [Plugin protocol](/reference/plugin-protocol#trace-context).

## Outbound TLS

`tls` configures `temporal`, `weaviate`, `postgres`, `s3` and `plugins` independently. All enabled TLS verifies the server certificate and name, using system roots by default, and requires TLS 1.2 or newer. There is no insecure verification mode or fallback to plaintext. [Run Quivr behind TLS](/run-quivr/tls) covers platform termination of incoming HTTPS; the engine's API and probe listeners serve plain HTTP.

Each dependency accepts these optional fields:

| Field | Default | Meaning |
| --- | --- | --- |
| `enabled` | See below | Explicit TLS on/off switch. For HTTP dependencies, it must agree with the endpoint scheme. |
| `ca_file` | System roots | Readable PEM CA bundle path, added to system roots. |
| `cert_file` | None | PEM client certificate path, configured with `key_file`. Refused for plugins. |
| `key_file` | None | Matching PEM private key path. Refused for plugins. |
| `server_name` | Endpoint host | DNS hostname or IP address to verify; DNS names are also sent as TLS server name. |

Temporal defaults to plaintext; enable it with `tls.temporal.enabled: true`. Its address stays `host:port`. Weaviate and S3 select TLS from their `https://` endpoint when `enabled` is omitted. An explicit switch never rewrites a URL: `true` requires HTTPS and `false` requires HTTP. TLS settings on a disabled connection refuse startup.

Weaviate and S3 redirects must stay on the endpoint's origin (scheme, hostname and port). Redirects to plaintext or another origin are refused before connecting, so client certificates remain with the configured dependency.

PostgreSQL uses `database_url` when `tls.postgres` is omitted: `sslmode=verify-full` verifies the certificate and hostname, with system roots unless the URL supplies `sslrootcert`. `sslmode=disable` selects plaintext. Opportunistic or unverified modes (`prefer`, the driver's default, `allow`, `require`, `verify-ca`) are refused. Explicit `tls.postgres` settings override the URL's TLS policy for every configured host and remove plaintext fallbacks; omitted `enabled` with certificate settings enables TLS. Prefer configuring trust in one place. URL certificate file options are still parsed, so remove obsolete file paths when switching to `tls.postgres`.

Plugin settings apply to discovery and every contribution call, including newly registered plugins and earlier pipeline plans. With omitted `enabled`, each endpoint selects HTTP or verified HTTPS; a CA bundle applies to HTTPS endpoints. Explicit `true` requires every plugin endpoint to use HTTPS. Explicit `false` requires HTTP and still preserves the connector rule: non-loopback connectors must use HTTPS. Plugin redirects are always refused. Plugin mTLS is not supported.

Unreadable or malformed certificate files, incomplete or mismatched client identity, disabled TLS with certificate settings, and URL/switch conflicts refuse startup with the dependency's name. Certificates load at startup; restart the API and worker after rotating them. Remote handshake failures make the dependency unavailable; they never trigger an insecure retry.

## API keys

`keys` maps each bearer token to what it may do. Every request's key decides its Organization, its actions and its Corpora:

```json
"keys": {
  "<random token>": {"organization": "acme", "actions": ["corpora:read", "content:write", "search:query"], "corpora": ["*"]}
}
```

| Field | Meaning |
| --- | --- |
| `organization` | The Organization the key acts for. Nothing crosses Organizations. |
| `actions` | What the key may do, from the list below |
| `corpora` | The Corpus ids it may reach, or `["*"]` for all of its Organization's Corpora. Creating a Corpus needs `*`. |

| Action | Allows |
| --- | --- |
| `corpora:read`, `corpora:write` | reading and creating Corpora |
| `content:read`, `content:write` | reading Records, Versions and Receipts; submitting and withdrawing content |
| `blobs:read`, `blobs:write` | reading upload sessions and Blobs; uploading files |
| `search:query` | searching |
| `changes:read` | reading the change feed |
| `monitoring:read`, `monitoring:write` | reading and managing Saved Queries, Subscriptions, Matches and Deliveries |
| `connectors:read`, `connectors:write` | reading and managing Connector Instances |
| `connectors:admin` | creating, listing, rotating and revoking a Connector Instance's push tokens on authorized Corpora; give it only to an operator key |
| `connector:push` | calling a source plugin’s declared API routes on authorized Corpora |
| `operations:read`, `operations:write` | reading, cancelling and rerunning Operations |
| `projections:rebuild` | starting a Corpus rebuild |
| `plugins:admin` | reading the plugin registry and registering and activating plugins (`/v0/admin/plugins`), backfilling a Corpus (`/v0/admin/backfills`) and promoting a vector space (`/v0/admin/spaces/{id}/promote`); give it only to an operator key |
| `observability:read` | following documents through their processing steps (`/v0/admin/documents`) and reading the counters of plugin calls, searches, steps, documents received and Matches (`/v0/admin/stats/*`) |

## Object storage

`s3` points at any S3-compatible store:

| Field | Meaning |
| --- | --- |
| `endpoint` | The store's URL, such as `https://s3.example.com` |
| `access_key`, `secret_key` | Its credentials |
| `bucket` | The bucket Quivr writes to; `quivr migrate` creates it when missing |

## Plugin pins

Each item of `plugins` pins one plugin. [Pin a plugin](/run-quivr/pin) explains how to use them.

| Field | Meaning |
| --- | --- |
| `manifest` | Path of the plugin's `quivr-plugin.yaml`, the exact file it was built from |
| `endpoint` | The plugin's base URL. A connector plugin needs `https://` unless it is on loopback. |
| `configuration` | The plugin's configuration, validated against the schema its manifest declares |
| `routes` | Normalizers only: the media types sent to it. Each route has a `media_type` and a `mode`, `required` (the default) or `optional`, which lets a `text/*` file fall back to plain text when the plugin fails. |
| `kinds` | Alert rules only: the alert kinds this deployment accepts, such as `["keywords"]`. Default: every kind the plugin declares. |
| `spaces` | Ingestion plugins only: the vector spaces to enable, each `served` or `evaluation`; exactly one is served. Default: the only declared space, served. |

## Ingestion routing

Several ingestion plugins can be pinned together. `ingestion` chooses one for each whole Record Version, using the media type of the submitted, verified Blob (`application/pdf`, `text/html`, and so on), or `text/plain` for inline text. Normalization preserves that source type: a PDF converted to text still follows the PDF route. Each selected plugin segments and embeds the Version's text Parts.

| Field | Meaning |
| --- | --- |
| `default` | Plugin id for source types without a route. Defaults to `core.ingest` when pinned, or the only ingestion plugin. With several other plugins, name a default. |
| `routes` | Map of exact source media types to pinned ingestion plugin ids. Invalid targets prevent startup. |
| `evaluation` | Map of source media types to lists of additional ingestion plugin ids. They fill independent projections after served enrichment succeeds. Targets must be pinned, distinct and different from that format's served plugin. |

Illustrative routing with both plugins pinned:

```json
{"ingestion": {"default": "core.ingest", "routes": {"application/pdf": "core.ingest", "text/plain": "example.hash_embedder"}}}
```

A plugin listed only for evaluation keeps its own segmentation and vector coverage. Evaluation work runs on separate activity capacity; a refusal, timeout or outage is recorded in the Version's diagnostics with the plugin id and never changes served readiness.

Each serving plugin owns its distinct vector spaces and serves one of them. Search uses the spaces whose owners have served projections in the requested Corpora. A plugin serving another source format does not encode an ordinary query for a Corpus where its projections are evaluation-only. Routes, defaults and evaluation selections are stored in immutable Pipeline Plans; work keeps the plan it started with during activation and rollback. Backfill an evaluation owner's primary space on past Versions before [activating it as served](/run-quivr/upgrade-a-plugin#promote-an-evaluation-plugin). Activation and rollback require complete coverage of each returning owner's own segments; the former projection stays available for rollback. Embedding image, audio or video Parts is a separate capability.

To measure an evaluation projection, send `evaluation_plugin` and `evaluation_space` together in `/v0/search`. The space must belong to that plugin and be carried by every requested Corpus. Omitted fields follow served routing. `GET /v0/corpora/{corpus_id}/vector-spaces` reports each owner's `total_segments` and fully covered `versions_covered`; different owners may cut the same documents differently.

The search protocol carries at most 16 enabled vector spaces, counting served and evaluation spaces across all pinned ingestion plugins. Startup refuses a configuration above that protocol limit.

## Search profiles

`retrieval.profiles` maps deployment short names to full `plugin_id/profile` names. Pin several retrieval plugins in `plugins`, then choose which profile serves each short name. An explicit map must contain `default`; every target must be declared by an installed retrieval plugin. Short names cannot contain `/` or surrounding whitespace.

This illustrative configuration selects profiles from two installed retrieval plugins:

```json
{
  "retrieval": {
    "profiles": {
      "default": "core.retrieve/default",
      "deep": "example.fusion_retriever/deep"
    }
  }
}
```

A deployment with one retrieval plugin and no map keeps its existing short names. Several retrieval plugins require an explicit map. Searches also accept full names directly. `GET /v0/search/profiles` lists every installed profile, its `full_name`, provider and `aliases`, including profiles without short names. Activating a new version replaces only that plugin; the map must still resolve in the new plan. [Search profiles](/run-quivr/search-profiles) explains short and full names with pictures.

## Webhook destinations

`destinations` maps a destination id, which Subscriptions name in `destination_id`, to where alerts are sent:

| Field | Meaning |
| --- | --- |
| `organization` | The Organization whose Subscriptions may use it |
| `url` | The receiver's URL. Private and loopback addresses are refused unless `delivery.allow_private_destinations` is set. |
| `secret` | The Standard Webhooks signing secret, `whsec_` followed by base64 |
| `secret_env` | The name of an environment variable holding the secret instead; prefer it in real deployments |

## Delivery

`delivery` tunes webhook retries. Every field is optional.

| Field | Default | Meaning |
| --- | --- | --- |
| `retry_initial` | `1s` | First retry delay; each retry doubles it, with jitter |
| `retry_max` | `5m` | Longest delay between two attempts |
| `window` | `24h` | How long a delivery is retried before it is `exhausted` |
| `timeout` | `10s` | Deadline of one attempt |
| `allow_private_destinations` | `false` | Allow loopback, private and link-local receiver addresses, including an internal webhook receiver in a self-hosted deployment. Startup logs a `WARN` when enabled. |

<Warning>
`delivery.allow_private_destinations` disables the startup and dial-time private-address guards. This increases server-side request forgery (SSRF) exposure: a configured receiver can reach internal services, including through DNS resolution. Enable it only for trusted destinations and restrict outbound network access. With the default `false`, both guards remain active.
</Warning>

## Change feed pruning

`change_prune` tunes when the worker deletes change-feed events older than `change_retention`. Every field is optional.

| Field | Default | Meaning |
| --- | --- | --- |
| `interval` | `1m` | How often the worker prunes |
| `retention` | `change_retention` | How long events are kept; shorter windows require `allow_short_retention` and named `organizations` |
| `organizations` | every Organization | Prune only these Organizations |
| `allow_short_retention` | `false` | Allow `retention` shorter than `change_retention` for explicitly listed `organizations`, for deployments accepting earlier change-event deletion. Startup logs a `WARN` when enabled. |

<Warning>
`change_prune.allow_short_retention` can permanently delete change-feed events before API cursors expire by age. Slow consumers can lose events and receive `410 cursor_expired`; they must resynchronize from the catalog. It does not delete canonical Records. With the default `false`, pruning cannot shorten the API retention window. Prefer setting a shorter `change_retention` consistently on api and worker when they should promise the same window.
</Warning>

## Backfill

`backfill` tunes [backfills](/run-quivr/backfill-a-vector-space). Every field is optional.

| Field | Default | Meaning |
| --- | --- | --- |
| `rate` | `2` | The most Versions per second one backfill processes. Worker only. |
| `concurrency` | `4` | Versions in flight inside a backfill step, range `1`–`32`; `0` selects the default. `1` restores serial work. Worker only. |
| `poll` | `5s` | How often a paused backfill checks whether it was resumed or canceled. Worker only. |
| `max_cost_without_confirmation` | `0` | The estimated cost, in US dollars, above which starting a backfill needs `confirm_cost`. With `0`, any backfill into a priced space needs it. Api only. |

Backfill concurrency controls overlap; `rate` still paces each batch. These limits apply per worker process. For hosted embeddings, also configure the plugin's `max_concurrent_requests`; provider `Retry-After` delays apply across that plugin process. Lower the limits for constrained providers or databases. Restart the worker after changing these engine limits.

## Observability

`observability` tunes the counters behind `/v0/admin/stats/*`. Every field is optional.

| Field | Default | Meaning |
| --- | --- | --- |
| `flush_interval` | `5s` | How often each process writes its counts; a process that crashes loses at most this much |
| `record_query_text` | `false` | Also count searches by their normalized query text, so the most frequent queries can be listed. The text is kept in PostgreSQL for 7 days and may hold personal or confidential information. |
