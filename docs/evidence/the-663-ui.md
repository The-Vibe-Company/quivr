Source: [Quivr PR #3714](https://github.com/The-Vibe-Company/quivr/pull/3714), commit `63d7fc52035190732b2c810c63645a295ece672e`, `quivr-search/`.

The requested better-ui and emil-design-eng skills were installed and read. Changes preserve the feather mark, purple accent, neutral surfaces, React/Phosphor stack and restrained search layout.

| Priority / location | Before | After | Reason |

| Medium / motion | General transitions | Named 120 ms transitions, pointer press scale .96, keyboard/reduced-motion suppression, transition-free theme changes | Keep repeated interactions immediate |

Initial browser tracer failed on the missing Add text action. Seven Chromium scenarios then passed against the real core and production facade: canonical Unicode round trip and hybrid search; session and route/corpus restrictions; mobile dark/reduced motion/keyboard/draft recovery; empty results/network error/retry; lost ingestion response replay; unavailable browser storage; terminal blocked enrichment. A separate HTTP facade test checks preservation of retryable upstream read failures and concealing out-of-corpus resources. Typechecking includes browser tests after a screenshot harness typo exposed a gap in that check.

Visually inspected screenshots: original 1440×1000; new desktop home, results and document; 375×812 dark home and input dialog. No horizontal overflow was observed; automated width assertions cover the mobile page and dialog. Screenshots/reports are generated by `make verify-demo` under `.scratch/quivr-demo-verify-*/`. CI retains screenshots/reports; traces stay local because they may contain session passwords and submitted text.

Limits: Chromium emulation, not physical iOS/Android or a screen-reader audit. Motion was inspected through CSS and reduced-motion behavior, not a slowed 10% playback recording. The shared-password demo is one shared space, not separate end-user accounts. Railway/domain delivery is THE-664.
